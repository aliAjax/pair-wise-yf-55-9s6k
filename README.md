# pair-wise-yf-55 动态表单规则编排和版本迁移模拟器

## 源提示词摘要
业务人员拖拽字段、设置分组、联动条件、计算规则、必填逻辑和多语言文案；发布前模拟旧数据在新结构下的迁移。系统比较版本差异，警告失效规则、循环依赖和引用删除，同时按历史版本解释过去提交的数据。

## 技术栈
React 19 + TypeScript + Vite + MUI + Redux Toolkit + RTK Query + React Router + React Hook Form + Zod/i18next + dnd-kit。

## 已实现闭环

### 发布：先编译不可变规则快照，再做循环依赖闸口
- 已发布版本（`FormVersion` + `CompiledSnapshot`）一旦写入即不可变；快照冻结字段、规则、联动边与结构指纹。
- 发布时编译联动依赖图（`field → rule → field`），DFS 检测循环依赖，并检查引用已删除字段的悬空规则；任一存在即拒绝发布（`src/engine.ts`）。
- 草稿区实时显示编译结果，发布前即可看到成环路径与失效规则。

### 旧数据：按原版本解释 + 按版本链懒迁移
- 30,000 条历史单据确定性生成（v1 占 60%、v2 占 40%），记录带提交版本戳记；回放只读该版本的不可变快照，绝不按当前草稿重新解释。
- 迁移沿 `parentId` 版本链逐版做字段映射（新增留空、删除丢弃、类型安全转换），输出每步差异。
- 懒迁移在记录被访问时触发，回写一条审计；不一次性改写全量数据。

### 后台迁移：分批、可中断、断点续跑
- 250 条/批、40ms 心跳；进度（已完成 id 桶）与紧凑审计元组持久化到 localStorage，审计有上限自动裁剪。
- 支持「处理 N 条后注入错误」演示：中断保留全部进度；暂停/继续、重试只扫描并补跑未完成/失败记录。
- owner + 心跳实现多标签页互斥；标签页崩溃后心跳过期才允许接管。

### 多标签页乐观锁：后到者不覆盖
- 草稿记录基线版本与指纹；发布点击时除 reducer 校验外，再直接读 localStorage 中的真实 head。
- 基线已变（对方已发布）时发布被拒绝：本地草稿原样保留，弹出冲突条并提示「重新比对」，可选以新版本为基线；无本地改动时仅显示漂移提示。
- `storage` 事件实时同步对方的发布与迁移进度。

### 其他
- 版本链/快照指纹差异对比、RTK Query 历史版本列表。
- 运行态表单按当前 head 快照动态渲染，联动显示/必填按快照边求值；新提交自动盖版本戳记。
- localStorage 持久化（state v2）。

## 验证建议
1. 加字段并添加一条指回自身的联动规则（A→B→C→A）→ 实时编译报循环依赖，发布被拒。
2. 删除被规则引用的字段 → 悬空引用报错，禁止发布。
3. 正常发布 v3 →「旧数据回放/迁移」输入 `rec-000001`，看到 v1→v3 懒迁移路径与审计。
4. 启动「中途注入错误」→ 约 800 条后中断，点重试，进度从断点继续直到 30,000。
5. 开两个标签页：A 页改字段并发布，B 页再点发布 → 冲突条出现，草稿保留且不覆盖对方。
